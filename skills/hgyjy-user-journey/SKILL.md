# hgyjy-user-journey — 对话式用户旅程图构建器

引导产品设计人员通过对话梳理用户旅程：从角色与场景出发，划分阶段、逐阶段填写七维度、标注事实/假设、绘制情绪曲线、提炼关键时刻，最终渲染为自包含 HTML 旅程图。

与 hgyjy-user-story（用户故事地图）的分工：**故事地图回答"做什么功能、按什么版本交付"（面向需求拆解与排期）；旅程图回答"用户怎么经历、在哪里受挫、机会在哪"（面向体验诊断与机会发现）**。二者数据独立，不要混用。

## 核心原则

1. **一张图 = 一个角色 × 一段场景**。同一人换目标就另起一张图，不要在一张图里塞多个角色。
2. **事实/假设分标是硬纪律**。每填一条内容必须问来源：是观察/访谈/数据得出的**事实**，还是团队推测的**假设**。假设阶段在图上以橙色列 + "假设"徽标呈现，提醒优先验证。
3. **对话产指令，脚本改状态**。LLM 不直接编辑 journey_map.json，而是生成结构化变更指令交给 `update_journey.py` 校验执行；渲染只读状态文件。这保证任何中断后都能从状态文件无损恢复。
4. **情绪分五档**：2 非常积极 / 1 积极 / 0 中性 / -1 消极 / -2 非常消极。不知道就留空（未评估），不要为了填满而编。

## 工作流程

### 阶段 1：定范围（必做）

向用户确认三件事，写入 journey 信息：

| 字段 | 含义 | 提问示例 |
|------|------|---------|
| `persona` 角色 | 具体的人，不是"用户" | "这个角色是谁？经验、技能、处境？" |
| `scenario` 场景与目标 | 一段具体情境 + 要完成的事 | "在什么情境下、要完成什么目标？" |
| `expectations` 用户预期 | 用户心里期待什么样的体验 | "他期望事情怎么发展？" |

一次性 `set_journey` 写入。范围含糊时先追问，不要边画边改角色。

### 阶段 2：划分阶段

引导用户把这段经历切成 **4–6 个阶段**（阶段名用名词短语，如"认知/首次提问/验证答案"）。用 `add_stage` 依次添加。阶段数少于 4 通常太粗，多于 7 则该考虑拆场景。

### 阶段 3：逐阶段填七维度 + 证据标注（主循环）

对每个阶段，按固定顺序问：**目标 → 用户行动 → 触点 → 想法/疑问 → 情绪 → 痛点 → 机会点**，每条内容追问"这是观察到的事实，还是推测？"，`add_item` 后按需 `set_stage` 标情绪与证据。

- 用户行动写"用户做了什么"（动词开头），触点写"通过什么渠道/界面/人"，想法写用户**原话式**内心独白。
- 痛点与机会点成对挖掘：每个痛点至少问一句"如果解决了会怎样"（机会点）。
- 追问话术参考 `references/methodology.md` 的七维度提问清单。

### 阶段 4：情绪曲线与关键时刻

全部阶段填完后：
1. 与用户过一遍情绪分，调整曲线形状；低谷（≤-1）阶段逐个确认痛点是否抓全。
2. 问"哪个瞬间决定了他还会不会再用？"提炼 2–4 个**关键时刻**（`add_moment`）。
3. 机会点按"痛点严重度 × 解决价值"口头排优先级，为后续需求转化做准备。

### 阶段 5：渲染与迭代

```bash
python3 scripts/render_journey.py --input journey_map.json --output journey_map.html
```

交付 HTML 后支持任意迭代：补条目、改情绪、标假设、调阶段名/顺序（删了重建）。每次改动先落状态文件再重渲染，保持单一事实源。

## 脚本用法

### update_journey.py — 状态文件增量更新

```bash
# 初始化（已存在则需 --force）
python3 scripts/update_journey.py --file journey_map.json \
  --changes '[{"op":"init","name":"工艺工程师首次使用知识库"}]'

# 批量变更（从 stdin 或 --changes 传入 JSON 数组，原子执行）
python3 scripts/update_journey.py --file journey_map.json --changes '[
  {"op":"add_stage","name":"首次提问","goal":"把问题描述清楚"},
  {"op":"add_item","stage":"首次提问","field":"actions","value":"拍照并文字描述缺陷"},
  {"op":"set_stage","stage":"首次提问","emotion":-1,"evidence":"hypothesis"}
]'
```

完整操作表与字段说明见 `references/schema.md`。批次中任何一条非法则整体拒绝、不落盘。

### render_journey.py — 渲染自包含 HTML

```bash
python3 scripts/render_journey.py --input journey_map.json --output journey_map.html
```

渲染前校验状态文件（阶段名唯一、情绪合法、条目非空等），校验失败拒绝渲染并列出全部错误。HTML 含：旅程信息面板、统计条、SVG 情绪曲线、逐阶段泳道列（目标/行动/触点/想法/情绪/痛点/机会点）、关键时刻面板；假设阶段橙色分标；支持 A3 横版打印。

## 迭代场景速查

| 用户说 | 做法 |
|--------|------|
| "加一个阶段 X" | `add_stage`，再补该阶段七维度 |
| "把阶段 X 的痛点改成…" | `set_item`（按 1-based 序号） |
| "这条其实是假设" | `set_stage` 的 `evidence:"hypothesis"` |
| "删掉阶段 X" | `delete`（级联删除该阶段全部内容，删前向用户确认） |
| "改角色/场景" | `set_journey`（提醒：改角色等于换图，建议另起新图） |
| "导出/重新生成图" | 重跑 render_journey.py |
