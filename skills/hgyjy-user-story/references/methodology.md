## 1. 原始需求七要素填写指引

| 要素 | 回答什么问题 | 好的填写 | 差的填写 |
|------|-------------|---------|---------|
| 需求来源 | 谁提出来的？客户/市场/售后/内部？ | "华南区头部客户 X 在季度回访中提出" | "领导说的" |
| 业务场景 | 在什么业务里、什么条件下发生？ | "五轴激光切割设备现场打样时，操作员需要…" | "加工的时候" |
| 现状痛点 | 现在怎么做、难在哪、代价是什么？ | "靠人工示教，单件调试 40 分钟，换型频繁时产能被吃掉一半" | "效率低" |
| 期望目标 | 做完要变成什么样？最好可量化 | "换型调试时间降到 10 分钟以内" | "提升用户体验" |
| 方案 | 打算用什么思路解决？（将被拆成旅程） | "相机拍照定位 + 自动找正 + 参数模板一键下发" | "做个自动化" |
| 价值 | 对客户/公司意味着什么？ | "单台设备日产能 +30%，可作为高配卖点" | "很重要" |
| DoD | 整体验收标准：什么情况算这个需求整体完成 | "在客户现场连续试运行 2 周无人工干预，定位误差 ≤ 0.05mm" | "功能都能用" |

## 2. 方案 → 用户旅程与用户行为分解

把 `solution` 当作一段用户要完成的事，拆成 3-7 个**有先后顺序**的步骤：

- **用户视角，不是系统视角**：写"操作员上料"，不写"系统加载物料表"。
- **动词开头，一句话说完**：「上料」「视觉定位」「自动找正」「轨迹生成」「加工」「质检」。
- **讲一个故事**：从左到右连起来读，应该能读成这个需求的完整使用过程。
- 超过 7 步：多半是混入了功能细节，往上归并；少于 3 步：方案可能还没想清楚，回到用户那里再挖。

分解时可直接问用户："如果我们把这套方案拍成一段操作视频，画面会分成哪几段？"

**旅程之下再分用户行为（可选层级）**：旅程是"阶段"，行为是用户在阶段内的具体动作。当一个阶段里用户有明显不同的几组动作时，拆成 2-5 个行为再挂特性；动作单一的阶段直接挂特性即可。

- 命名对照：旅程用阶段名（「上料」「自动找正」），行为用动词短语（「上传文档」「审核条目」「拍照建模」），特性才是能力点（「视觉定位计算」）。
- 判断要不要行为层的问法："在这个阶段里，用户的手和脑子分别做了哪几件事？"

## 3. 功能特性四要素提问清单

对每个旅程步骤逐问：

- **Who**：谁在使用？操作员 / 工艺工程师 / 设备管理员 / 系统自动？——同一个步骤可能有多个 Who，拆成多个特性。
- **When**：什么时机、什么条件触发？上电后 / 换型时 / 报警后 / 每次加工前？
- **Why**：为什么要这个特性？做了给谁带来什么价值、消除哪个痛点？一句话说清；写不出 Why 的特性往往该砍或合并。
- **What**：要完成什么？写一个可交付的能力点，特性名称取它的简短动宾短语（≤15 字）。
- **DoD**：怎样算这条特性做完了？——**可测试、可量化、含边界**：
  - 量化句式："X 在 Y 条件下达到 Z 指标"，复用组织内已有的精度/效率标尺，不自造标准；
  - 必须包含异常边界："夹具放反时能识别并报警，不允许加工"；
  - 差的 DoD："界面友好""响应快"；好的 DoD："从拍照到输出找正结果 ≤ 3s，重复定位误差 ≤ 0.05mm，图像模糊时明确报错"。

追问技巧：用户答不出 DoD 时，问"这条特性交付后，你在现场拿什么演示给需求方看？那个画面里哪些指标是对的？"

## 4. 版本切分原则

- **R1（MVP）= 端到端能走通的最薄路径**：每个旅程步骤至少有一条 must 特性，串起来能完成一次真实业务闭环。
- 优先级判据：缺了业务闭环就断的是 must；显著提升效率/体验的是 should；锦上添花是 could；明确本次不做记 wont。
- 切完 R1 后回读给用户："R1 交付后，用户能独立完成的最小完整流程是……对吗？"

## 5. 常见错误与纠正

| 错误 | 表现 | 纠正 |
|------|------|------|
| 系统视角 | "系统计算轨迹"当旅程步骤 | 改成用户动作："确认加工路径" |
| 把特性当旅程 | 旅程步骤下直接写细节功能 | 旅程是"段"，特性才是"点" |
| 行为与特性混级 | 行为写成能力点（"视觉定位计算"当行为） | 行为写用户动作（"拍照建模"），能力点挂到行为下 |
| 层级一刀切 | 所有旅程强制都建行为层 | 动作单一的阶段直接挂特性，行为层按需启用 |
| DoD 写成任务清单 | "完成界面开发、联调通过" | 改成验收结果，开发任务不填 |
| 版本按模块切 | R1=全部界面，R2=全部逻辑 | 按业务闭环切，不按技术分层切 |
| 特性漏异常流 | 只有 happy path | 每步追问"失败了会怎样" |
| 一张图塞多个需求 | 用户想把两个需求画在一起 | 坚持一图一需求，拆图 |
